# Channel Feature List

## Scene Construction

- Declarative `Scene(...)` built on `witwin.core.SceneBase`, `Structure`, `Material`, `Mesh`, and shared geometry primitives.
- `import witwin.channel as wc` is the user-facing channel umbrella. It exports `Scene`, `Transmitter`, `Receiver`, `ReceiverGrid`, `Box`, `Material`, `Structure`, core DrJit aliases, and solver namespaces `wc.path`, `wc.deterministic`, and `wc.montecarlo`. Solver implementations and shared internal helpers now live under `witwin.channel.*`, including `witwin.channel.path`, `witwin.channel.deterministic`, `witwin.channel.montecarlo`, `witwin.channel._config`, and `witwin.channel._native`.
- Channel-owned shared utilities and scene runtime now live under grouped `witwin.channel.core` packages: `numerics`, `geometry`, `physics`, `runtime`, `results`, `scene`, and `kernels`. The old top-level channel utility and scene packages are removed without compatibility shims; examples should use `import witwin.channel as wc` or explicit grouped `witwin.channel.core.*` imports.
- Solver public configs now use interaction-neutral names: `num_samples`, `max_bounces`, and `max_diffraction_order`. The old public `reflection_n_rays`, `reflection_max_bounces`, and `max_diffractions` constructor fields are removed.
- Diffraction edge policy is now solver configuration, not scene construction. Path, deterministic, and Monte Carlo configs expose one edge-policy entrypoint, `edge_policy=EdgePolicy(...)`; the old direct `edge_selection_mode`, `vertical_ratio`, `edge_diffraction`, and `boundary_edge_policy` config fields are removed. `EdgePolicy` now rejects contradictory `edge_diffraction` / `boundary_edge_policy` requests instead of silently overriding them, and its default selects all diffraction edges instead of vertical-only edges.
- Public deterministic radiomap and path solver configs no longer expose `ray_mode`. Standard solves use 3D tracing by default, and shared result-level ray mode normalization now lives under `witwin.channel.core.results`.
- Advanced solver controls now live under nested config objects instead of the top-level public constructor. Path and deterministic solvers expose `Tuning`; Monte Carlo exposes `Tuning` plus `IntegratorOptions` for integrator selection, AD intent, seed, roulette, and sample-budget controls. Public `return_timing=` flags are removed from standalone path and Monte Carlo solves; timing is reported in result metadata.
- Multi-structure scene assembly through `Scene(structures=[...])` and a unified `Scene.add(obj)` that dispatches over `Structure`, `Transmitter`, `Receiver`, and `ReceiverGrid`.
- Low-level scene visibility helpers now delegate `Scene.segment_visible(...)`, `Scene.segment_pair_visible(...)`, `Scene.segment_chain_visible(...)`, and `Scene.axial_edge_visible(...)` to RayD trace-visibility dispatch. Unsupported controls such as structure-level ignores or native visibility calls inside Dr.Jit symbolic recording raise immediately instead of falling back to Python re-fire loops. Monte Carlo shadow-boundary source-edge pre-culling now uses RayD axial edge visibility instead of looping over per-fraction segment tests.
- Monte Carlo basic and BDPT reflection now default `IntegratorOptions(accumulation_backend="auto")` to RayD `accumulate_reflections` for primal and AD tape-collection solves. The RayD path atomically accumulates complex-polarized reflection field and power into the receiver grid, preserves AD inputs through RayD-native AD overloads, passes endpoint TX polarization through to RayD, converts RayD wedge events into the existing diffraction handoff store with prefix-aware source point, source power, initial direction, and bounce-depth payloads, reports `cell_accumulation_mode="rayd_optix_atomic_add"` in metadata, uses compact static sampling metadata, and raises instead of falling back when RayD support, complex field payloads, or wedge-buffer capacity are unavailable.
- Monte Carlo first-order diffraction now exposes `DiffractionExecutionConfig.accumulate_primal="auto"|"drjit"|"rayd_optix"`. The `auto` mode resolves to RayD OptiX accumulation for both primal and AD tape collection. RayD mode dispatches basic and BDPT order-1 diffraction to RayD `Scene.accum_dfr_direct`, atomically accumulates scalar power into the receiver grid, preserves direct, Keller, and suffix-reflection AD inputs through RayD-native CUDA custom-op JVP/VJP, and records `cell_scatter_backend="rayd_optix_atomic_add"` in diffraction runtime metadata. The old Monte Carlo `accumulate_jvp` / `accumulate_backward` Dr.Jit replay selectors are removed from `DiffractionExecutionConfig`; AD mode now follows the selected RayD/native execution path instead of exposing a second derivative backend knob. BDPT AD reflection-coupled suffix diffraction now stays on RayD native suffix-reflection JVP/VJP instead of silently entering the old slow replay path. BDPT RayD large-workload suffix sampling caps the suffix budget, pushes reflection-prefix wedge sampling into the RayD reflection kernel with source-power stride compensation, samples a compact source-power-rescaled reflection-prefix state table, and uses RayD terminal-state adjacent-face suffix candidates instead of global uniform triangle candidates. BDPT RayD prefix/suffix budgets now use an adaptive bucket policy keyed by scene edge count, receiver-grid cell count, sample count, and reflection depth; prefix state compaction preserves edge-bucket coverage and rescales source power per bucket while reporting the resolved caps in runtime metadata. BDPT order-2 and order-3 direct receiver-cell, Keller-chain, and terminal suffix-reflection accumulation use RayD `Scene.accum_dfr` in explicit `rayd_optix` mode with no mixed Dr.Jit strategy path for strict native forward execution; native AD for higher-order direct, Keller, and suffix-reflection chain strategies is handled by RayD handwritten JVP/VJP over the fixed OptiX tape.
- Deterministic matched-isotropic coherent diffraction now uses RayD `Scene.accum_dfr_coherent_direct` in `DiffractionExecutionConfig.accumulate_primal="auto"` for supported primal workloads up to third-order diffraction: axis-aligned receiver grids, no suffix diffraction, no shadow-support cutoff override, and no AD-sensitive scene/state inputs. The RayD path consumes the full Channel UTD state payload, evaluates the Channel native vector formula in OptiX, disables legacy receiver tiling when the grid accumulator is active, records `implementation="rayd_accum_dfr_coherent_direct_exact"` in diffraction metadata, and keeps AD workloads on the existing DrJit/native path until RayD fixed-topology coherent diffraction derivatives are implemented.
- Deterministic first-order coherent diffraction state preparation now routes supported non-AD Tx-to-edge state construction through RayD `Scene.build_dfr_coherent_tx_states`, moving Tx visibility, source exterior masking, incident Jones/vector payload generation, material payload packing, and compact state emission into the RayD native path while preserving the existing DrJit path for AD-sensitive workloads.
- Deterministic higher-order coherent diffraction candidate discovery can now call RayD `Scene.build_dfr_coherent_higher_candidates` for supported non-AD RayD edge-BVH workloads, moving the outgoing-basis probe construction and scene-global-to-local edge candidate compaction behind a narrow RayD API while Channel continues to own dedupe, UTD field evaluation, state lineage, and AD fallback. Supported non-AD BVH workloads can also request RayD visibility-filtered coherent edge candidates, avoiding the duplicate Channel `segment_visible` pass while preserving the old AD and topology-preserving paths.
- Deterministic diffraction builder reports now include per-order higher-order stage timings for pre-expansion pruning, higher-order state construction, inserted reflection expansion, post-budget pruning, lineage finalization, and total order time, so RayD migration work can identify the next dominant state-preparation bottleneck from solver metadata.
- `witwin.channel.core.scene.Scene.load_mitsuba(...)` loads Sionna RT / Mitsuba XML scenes such as the bundled Munich scene through `sionna.rt.load_scene`, converts them into `witwin.core.Structure`, `Material`, and `Mesh` objects, preserves source/load metadata, supports Sionna merge-shape and duplicate-vertex controls, and includes bounded `256 x 256` Munich deterministic, basic Monte Carlo, and BDPT radio-map notebooks with explicit RayD diffraction backends, `1_000_000`-sample Monte Carlo budgets, aligned Sionna RT result comparisons, and a transmitter rooftop-placement geometry check.
- `Scene.load_mitsuba(...)` and `Scene.from_sionna(...)` store imported XML/open-mesh edge-policy metadata without adding scene-construction edge-policy parameters. Solvers select boundary behavior with `edge_policy=EdgePolicy(boundary_edge_policy=...)`.
- `witwin.channel.core.scene.Scene` now supports scene-owned `Transmitter`, `Receiver`, and `ReceiverGrid` endpoints. Standalone deterministic, path, and Monte Carlo solves can select named scene endpoints with `transmitter="..."` and `receiver="..."`, with transmitter power and endpoint polarization owned by the endpoint objects instead of solver config. Deterministic, path, and Monte Carlo public config classes reject physical setup fields such as transmitter power, material coefficients, material overrides, and endpoint polarization; material response is taken from per-structure `witwin.core.Material`. Channel scene mesh insertion also requires an explicit `witwin.core.Material`; implicit default material creation is rejected.
- Standalone deterministic and Monte Carlo radiomap solves now return the same shared `RadioMapResult` payload and no longer expose generic public `Result` aliases. Public radiomap solves select scene-owned transmitter and `ReceiverGrid` endpoints with `transmitter=` and `receiver=`; `tx_pos=` and `grid=` are removed from the public radiomap solver signatures.
- `examples/monte_carlo_radiomap_basic_munich.ipynb` provides a raw first-order Munich comparison path for `Config(max_diffraction_order=1, integrator_options=IntegratorOptions(integrator="basic"))` against Sionna RT `max_depth=1`, with matched XML, transmitter, frequency, grid, sample budgets, edge diffraction enabled on both sides by default, component maps, dB delta summaries, and opt-in smoothing/filtering kept separate from the default parity run.
- Declarative field monitor support through `FieldMonitor`, `Scene(monitors=[...])`, and `Scene.add_monitor(...)`, with `Tracer.trace(tx_pos=..., monitor=...)` overriding scene monitors when provided and otherwise using the scene-declared monitor set.
- Declarative path monitor support through `PathMonitor`, so `Scene(monitors=[...])` and `Tracer.trace(..., monitor=...)` can request discrete receiver-path output alongside plane fields. Single-monitor path traces now return a DrJit-native `PathResult` directly, while mixed-monitor traces return a `dict[name, payload]`: path amplitudes remain native DrJit `Complex2f` arrays, scalar/index/geometry payloads are exposed as shaped DrJit tensors, and CIR/CFR/tap helpers still provide torch tensors on demand for downstream analysis.
- Standalone path solving is available through `witwin.channel.path`: `solve(...)` accepts a `witwin.channel.core.scene.Scene`, scene-owned `Transmitter` and `Receiver` endpoints selected by name/object or endpoint lists, and a path `Config`, then returns `PathResult` with LoS/reflection/diffraction path coefficients, delays, AoD/AoA angles, interaction types, optional geometry, metadata, and CIR/CFR/tap helpers. Raw coordinate `tx_pos=`, `receiver=`/`receivers=` duplication, and the generic public `Result` alias are removed.
- Standalone path solving now resolves `Tuning(reflection_field_backend="native")` reflection field replay to strict RayD OptiX EPC by default, while explicit `reflection_field_backend="drjit"` disables RayD EPC. First-order path diffraction with `DiffractionExecutionConfig.accumulate_primal="auto"` also resolves to RayD `Scene.trace_dfr_paths` by default, preserves AD transmitter/receiver inputs through RayD-native AD overloads, maps compact native output into the existing `PathResult` contract with optional geometry, reports `runtime_backends.reflection` / `runtime_backends.diffraction` metadata, and raises on unsupported higher-order or unavailable-native workloads instead of falling back.
- Higher-order standalone path diffraction now keeps the Dr.Jit state-materialization route on the reduced path-export layout, avoids a final full-state concat before sparse path export, reuses the selected RayD edge mask across all higher-order expansion steps in a state-preparation pass, caches no-geometry AoD/AoA/depth summaries in `diffraction_state_refs_v1`, and reconstructs only selected interaction-type slots during result assembly. Munich 1e6-ray order-2/order-3 stress records are kept under `docs/dev/optimization/`.
- Scene-level RF capability v1 adds `Scene(frequency=..., tx_array=..., rx_array=...)`, endpoint-level `array=` overrides, `AntennaArray`, `PlanarArray`, `ULA`, and `UPA` exports from `witwin.channel`, arbitrary differentiable element positions/orientations, dual/custom complex polarization slots, built-in `iso` / Sionna-compatible short-`dipole` / `tr38901` pattern evaluation, late-bound `Material.from_itu(...)`, and solver-visible material `mu_r`. Public path, deterministic, and Monte Carlo `solve(...)` calls now read `Scene.frequency` instead of accepting `frequency=...`; path CIR/CFR/tap helpers use the Sionna-compatible antenna/time axes, while radiomap `path_gain`, `rss`, and `sinr` expose a leading TX axis plus `best_tx_index`, `cell_association()`, and `squeeze_tx()`, with multi-TX radiomap stacking preserving DrJit gradients.
- `Tracer.trace(..., monitor_overrides={...})` applies trace-local monitor overrides without mutating scene-attached monitors, so callers can override discrete receiver sets (`PathMonitor.positions`) or field-plane parameters per simulation call. `Tracer.trace_many([...])` runs multi-TX sweeps in one API call and returns one payload or `dict[name, payload]` per request, with each batch item able to override `tx_pos`, the monitor list, and monitor-local receiver definitions independently.
- `FieldMonitor(..., max_diffractions=...)` and `PathMonitor(..., max_diffractions=...)` can override diffraction order per monitor without changing the tracer-wide trace config. `max_diffractions=None` inherits the tracer setting, while `PathMonitor` defaults to first-order diffraction so discrete path export stays bounded unless a deeper order is requested explicitly.
- Declarative `RadioMapMonitor` support through `Scene(monitors=[...])`, `Tracer.trace(..., monitor=...)`, and `Tracer.trace_many(...)` adds cell-centered radio-map measurement surfaces alongside field and path monitors. The radio-map contract is distinct from `FieldMonitor`: cells are evaluated at cell centers or fixed quadrature points, metrics are exposed as power maps (`path_gain`, `rss`, `sinr`) with selectable `combine_mode="incoherent"|"coherent"` semantics plus an explicit `receiver_model="matched_isotropic"|"projected_polarized"` contract surfaced on both `RadioMapMonitor` and `RadioMapResult`, radio-map traces default to first-order diffraction unless `max_diffractions` is set explicitly, optional coherent diagnostics remain available, `trace_many(...)` can fill multi-transmitter SINR and transmitter-association maps while aggregating RSS in a streaming post-pass without materializing an extra dense TX stack, `RadioMapResult.sample_metric_positions(...)` can sample world-space positions from the computed map under metric and association filters, direct-diffraction state preparation now reuses AD-safe persistent caches across repeated radio-map traces when the transmitter/scene/solver signature is unchanged, tracer-level reflection discovery is shared between radio-map and path monitors when they request the same sampling family, `RadioMapMonitor(..., accumulation_backend="auto"|"baseline"|"native_coherent"|"cell_accumulation"|"native_monte_carlo")` exposes explicit backend control, and `RadioMapMonitor(..., sampling_mode="deterministic"|"monte_carlo", ad=True|False|None)` now separates the existing fixed-quadrature cell solver from a dedicated transmitter-driven Monte Carlo mode with `samples_per_tx`, `rr_depth`, `rr_prob`, `stop_threshold`, and `seed` controls plus explicit AD intent. Supported axis-aligned incoherent radio maps now default to `receiver_model="matched_isotropic"` while coherent or oriented workflows keep `projected_polarized` unless overridden, matched-isotropic incoherent maps can now also fall back to the baseline backend when native direct-cell accumulation is unavailable, matched-isotropic coherent axis-aligned radio maps now run on the same low-overhead direct-cell EPC path by accumulating per-cell vector coherent sums instead of adding new rays or supersampling, axis-aligned coherent radio maps with `receiver_model="projected_polarized"` still auto-select the native reflection-plus-diffraction accumulation path when the native CUDA backends are available and compatible, that native coherent path now preserves reverse-mode gradient flow through `path_gain` and coherent-power diagnostics for transmitter position, triangle-material, and triangle-vertex inputs by switching reflection EPC onto the gradient-preserving native CustomOp path when needed, fresh gradient-disabled coherent radio-map traces now also keep reflection accumulation on the requested native backend instead of silently falling back to exact receiver EPC when the monitor/grid is epc-eligible, supported axis-aligned gradient-disabled incoherent radio maps now also auto-select a radio-map-owned native backend that writes reflection/diffraction scalar-power contributions directly into final cell buffers during EPC instead of deferring them to a post-pass reducer, that cell-accumulation path now applies matched-isotropic vector-power accumulation when requested, and the new `sampling_mode="monte_carlo"` path keeps the dominant runtime tied to `samples_per_tx` instead of dense grid replay by sampling measurement-surface hit points, evaluating LoS plus exact reflection power and sampled diffraction-state power at those points, and scattering weighted scalar power into the final map through a dedicated bundled CUDA kernel. AD-enabled `sampling_mode="monte_carlo"` workloads now stay on that same transmitter-driven solver instead of switching to a second solver: `ad=True` keeps the symbolic-loop primal on `native_monte_carlo`, records a compact Monte Carlo sparse-coefficient tape from that same run, and routes JVP/VJP through an outer CustomOp backed by dedicated Monte Carlo native kernels under `witwin/channel/monitors/radio_map/monte_carlo/native/`, with pathwise-fixed discrete events and no deterministic replay fallback, while `ad=False` detaches the same solver path and `ad=None` auto-resolves from grad-enabled inputs. The unified Monte Carlo path reports `metadata["monte_carlo"]["ad_mode"]`, `metadata["monte_carlo"]["ad_backend"]`, `metadata["monte_carlo"]["tape_layout_version"]`, and keeps `metadata["accumulation_backend"]["resolved"] == "native_monte_carlo"` for both AD and non-AD workloads. Monte Carlo AD now also keeps dedicated LoS/reflection TX-transport tapes for candidate ray states, replays fixed-topology blocker distances on coplanar surface groups, and reports the selected TX accumulation transport mode/step in Monte Carlo metadata so `tx_x` accumulation diagnostics can distinguish pathwise sparse-coefficient terms from fixed-tape transport terms. Projected-polarized incoherent diffraction pair EPC now reports and uses the direct-state scalar backend instead of the older native pair-EPC path to avoid dense-map live-storage retention on large wall maps, matched-isotropic incoherent radio maps can now optionally enable `shadow_boundary_mode="utd_cross_term_surrogate"` to add UTD transition-weighted LoS/reflection-to-diffraction cross terms into the reported `path_gain` while preserving the raw component powers in diagnostics, projected-polarized coherent radio maps can now optionally enable `shadow_boundary_mode="projected_isb_completion"` to add a low-overhead angular shadow-side direct-field completion term to the reported coherent `path_gain`, and that completion is now also folded into the exported coherent `diffraction` / `total` diagnostics so radiomap diffraction maps stay smooth across exterior shadow boundaries while closed-mesh interiors remain zero, matched-isotropic coherent radio maps can now optionally enable `shadow_boundary_mode="matched_isb_completion"` to apply a scene-edge weighted average of complex incident UTD transition responses, then subtract the incident-weighted direct-mode excess already present in the raw LoS-plus-diffraction field before reporting the low-overhead ISB-smoothed coherent `path_gain`, with the completion weights and transition responses honoring the scene's explicit finite edge bounds instead of assuming infinite wedges, and the matched-isotropic coherent `diffraction` / `total` diagnostics now fold in that completion as well so exterior shadow boundaries stay smooth without leaking through closed meshes. The native matched-isotropic coherent path now also keeps the final vector-power reduction, the per-edge ISB incident-statistics replay, and the matched-ISB completion algebra on bundled native CustomOps with explicit forward-mode JVP and reverse-mode VJP support for `tx/rx/edge_pos`, and the maintained three-cube radiomap gradient workflow now exercises `tx_x` / `cube1_x` AD-vs-FD checks on that contract. Grad-sensitive baseline matched-isotropic coherent diffraction replay now also bypasses the old sparse `pair_valid` power replay path and instead performs dense per-group UTD vector accumulation with zeroed invalid contributions before receiver-side symbolic vector-power reduction, while higher-order edge-to-edge state transport in that same grad-sensitive path now preserves candidate topology and reuses the existing exterior-shadow completion contract without requiring a closed-mesh interior query, which keeps maintained three-cube order-2 diffraction state counts stable across FD perturbations without switching AD traces onto the heavier FieldMonitor workflow. Meanwhile, the cell-accumulation matched-isotropic replay path now accepts `RadioMapMonitor(..., shadow_support_cutoff_db=...)` to clip the shadow-side replay band by energy threshold relative to the face-anchor completion energy, pre-culls diffraction pairs with that cheap bounded shadow-support mask, and uses a smaller radio-map-owned pair chunk budget so high-resolution finite-wedge radiomaps stop replaying zero-valued deep-shadow pairs and avoid the previous `512 x 512` OOM pattern without turning the monitor into a full field-style replay, axis-aligned gradient-disabled matched-isotropic coherent radio maps with `max_diffractions=0` now also run a dedicated no-diff fast path that forces dense reflection-family replay, skips diffraction-state/completion-surrogate setup that is irrelevant to the no-diff case, and records `metadata["runtime_backends"]["no_diff_fast_path"]` plus `metadata["runtime_backends"]["no_diff_reflection_scheduler"]` for the maintained `256 x 256 / 384 rays` acceptance workload, native coherent and cell-accumulation radio-map timing metadata now include `state_preparation_seconds` so reported `total_seconds` covers diffraction state layout/build work instead of only the downstream accumulation passes, radio-map reflection and diffraction now resolve receiver tiling through a radio-map-owned scheduler instead of directly borrowing field-monitor tiling policy, coherent diffraction suffix tracing now routes through a monitor-neutral suffix module instead of a field-only adapter, runtime metadata now reports explicit `radio_map_coherent` / `radio_map_incoherent` execution intents plus the resolved receiver model, requested/resolved radio-map accumulation backend, cell-accumulation mode, TX-stack aggregation mode, and the reflection/diffraction/suffix kernel backends that were actually used, and both axis-aligned and oriented planar surfaces are supported through the same `Scene + Tracer + payload/dict` trace contract.
- `RadioMapMonitor(..., sampling_mode="monte_carlo")` now uses a true TX-emitted ray-driven accumulation path for axis-aligned matched-isotropic incoherent maps with a single `samples_per_tx` sample budget per transmitter: LoS is evaluated per receiver cell center with a direct visibility test instead of depending on sampled plane hits, the initial reflection launch set is a full-sphere Fibonacci distribution, specular reflections are accumulated in-loop from the active ray/image-source state, and first-order diffraction now samples TX-visible finite edges proportionally to edge length, samples a point on the edge, launches a Keller-cone ray to the monitor plane, and weights the hit by the diffraction Jacobian instead of replaying receiver targets. The standalone basic Monte Carlo contract intentionally caps diffraction at `Config.max_diffraction_order <= 1`; the BDPT integrator owns depth-limited diffraction sampling up to third order.
- `witwin.channel.montecarlo.Tuning.shadow_boundary_mode` now defaults to `"utd_power_smoothing"` for matched-isotropic incoherent Monte Carlo radio maps. The solver keeps raw non-negative LoS/reflection/diffraction power diagnostics, scatters UTD transition-weighted diffraction proxy powers for incident and reflection shadow boundaries, adds stable cell-centered UTD shadow-boundary geometry weights and complex `F(kLa)` transition responses so high-resolution maps are not limited by sparse diffraction sample hits, and reports `path_gain` from `raw_total + shadow_boundary_correction`. The correction replaces hard GO plus raw transition-band excess with the UTD continuation coefficient `0.5*(1 +/- F)` in the power domain and is clamped only to keep total power non-negative. It no longer applies a local-neighbor hard-boundary fallback or forces the `F(0)` boundary limit, so the active path is the reported UTD transition-weighted completion. The cell-centered shadow-boundary geometry weights now taper continuously in a narrow Fresnel-scaled band around explicit finite-edge endpoints, so finite wedge endpoints fade incident/reflection transition geometry maps instead of leaving a hard stationary-point cutoff. `Tuning.shadow_boundary_backend="auto"|"drjit"|"native_candidate"` now controls large-scene smoothing execution: small workloads keep the Dr.Jit reference path, while large edge-cell products require the native candidate backend, which uses conservative edge-tile candidate pruning plus bundled CUDA accumulation and reports backend, tile shape, candidate count, and candidate ratio in Monte Carlo metadata. `shadow_boundary_mode="none"` preserves the previous raw incoherent sum for diagnostics and kernel-history comparisons. The maintained Monte Carlo three-cube and BDPT notebooks now expose signed `shadow_boundary_correction` plots separately from the raw component powers, with the Munich BDPT notebook enabling automatic native candidate smoothing and showing the candidate statistics.
- Monte Carlo UTD power smoothing now pre-culls shadow-boundary edges by source visibility before native candidate generation, restricts smoothing to the integrator's active diffraction edge support, gates incident continuation by the receiver cell's direct LoS state or matching first-blocker surface group, and applies final incident/reflection correction only where sampled diffraction transition power exists for that boundary family. Large multi-mesh scenes such as Munich therefore avoid hidden-edge fan saturation, unrelated-edge incident fan leakage, and all-edges shadow-boundary continuation in dark cells, while Monte Carlo metadata reports source-visible edge counts, source visibility samples per edge, incident-support policy, and the active weight aggregation policy.
- Standalone Monte Carlo radiomap access is available through `witwin.channel.montecarlo`: `solve(...)` accepts a `witwin.channel.core.scene.Scene`, scene-owned transmitter and `ReceiverGrid` endpoints, and a `Config`, returns `RadioMapResult`, and dispatches through an explicit integrator layer with `Config(integrator_options=IntegratorOptions(integrator="basic"|"bdpt"))` so ray-family composition and sampling live under `witwin/channel/montecarlo/integrators/` instead of a generic tracer module. The `basic` path uses per-cell LoS plus TX-emitted specular reflection and first-order sampled diffraction. The `bdpt` path is now a staged primal BDPT implementation with per-cell LoS, forward-constrained specular reflection, and active depth-limited wedge diffraction MIS up to `max_diffraction_order=3`: the `IntegratorOptions.samples_per_tx` diffraction budget is split by diffraction order and then across direct wedge-to-cell, Keller-cone plane-hit, and single-bounce specular suffix-connection strategies, with metadata recording the mixed discrete receiver-cell and continuous plane-hit PDF measures. BDPT also seeds reflection-prefix diffraction states from forward-generated specular reflection hits, so `R^n -> D` and `R^n -> D -> ... -> D` families are sampled without constructing arbitrary reflection paths, and it samples `... -> D -> R` suffix paths through a one-surface image-method specular connection. The package no longer ships a package-local scene adapter module or scene wrapper, and its scene access now goes through `witwin.channel.core.scene.Scene` plus `Scene` internal helper methods that reuse the shared `witwin.channel.core.scene` runtime/build APIs instead of a package-owned support layer. The package also includes a minimal onboarding example in `examples/monte_carlo_radiomap_minimal.py`, a BDPT-focused notebook in `examples/monte_carlo_radiomap_bdpt.ipynb`, and a package-architecture overview under `docs/dev/standards/42-monte-carlo-radiomap-package-overview.md`. Its axis-aligned primal accumulation path now uses a graph-owned native CUDA scatter-delta kernel in the production solve instead of Dr.Jit `scatter_reduce()`, and the exported runtime metadata reports that backend explicitly through `metadata["accumulation_backend"]["cell_accumulation_mode"]` and `metadata["runtime_backends"][...]["cell_scatter_backend"]`.
- Monte Carlo basic and BDPT reflection tracing now uses top-level `Config.num_samples` as the actual TX-emitted specular reflection ray budget independently from the `IntegratorOptions.samples_per_tx` diffraction budget. Runtime metadata exposes the effective reflection ray budget, reflection solid angle, and separate diffraction sample count so high-resolution Sionna comparison notebooks can verify that reflection density is aligned instead of silently inheriting the smaller diffraction sample count.
- `witwin.channel.montecarlo.Config(filtering=...)` now supports opt-in differentiable incoherent power-domain denoising for standalone Monte Carlo radio maps. `FilterConfig` and `ComponentFilterConfig` can independently enable Gaussian or bilateral-style filters for `incoherent["reflection"]` and `incoherent["diffraction"]`, leaving LoS and coherent diagnostics untouched. Filtering is disabled by default, runs before `raw_total`, shadow-boundary correction, `path_gain`, `rss`, and `sinr` are finalized, keeps shadow-boundary diffraction transition-power auxiliaries filtered with the diffraction component so completion does not subtract stale raw spikes, stays Dr.Jit-native so gradients flow through the filter transform, and reports its enabled/disabled contract in `metadata["monte_carlo"]["filtering"]`.
- Monte Carlo BDPT diffraction now applies material gain to both the direct UTD edge term and face-reflection UTD terms, and reflection-prefix diffraction states use stable ray/depth slots with forward solid-angle source weights. This keeps `R^n -> D` families deterministic across repeated notebook runs and prevents reflection-prefix samples from being implicitly counted as an exhaustive source set.
- Monte Carlo BDPT diffraction now defaults to `IntegratorOptions.bdpt_diffraction_sampling="sobol"` for the depth-limited MIS estimator. Edge-chain state selection, edge-position sampling, receiver-cell / suffix-primitive choices, and Keller-cone angle sampling use stable multi-dimensional Sobol samples with per-seed digital shifts; `bdpt_diffraction_sampling="hash"` remains available for direct comparisons against the previous hash-uniform sequence.
- First-order Monte Carlo BDPT diffraction now importance-samples candidate diffraction edges with a mixed edge-length, receiver projected solid-angle, source-distance, and source-power proposal. The estimator keeps a positive edge-length baseline and applies per-sample PDF correction, so the one-diffraction direct and Keller strategies spend more samples on edges that can contribute to the receiver surface without changing the UTD contribution formula.
- `witwin.channel.montecarlo.Config(integrator_options=IntegratorOptions(integrator="bdpt", ad=True|None))` now supports pathwise fixed-topology AD instead of raising at the BDPT boundary. The AD path records one primal BDPT tape for LoS, forward specular reflection, direct wedge-cell diffraction, Keller cone plane-hit diffraction, and single-bounce suffix reflection up to `max_diffraction_order=3`, replays fixed visibility/MIS/discrete topology through an outer Dr.Jit `CustomOp`, and routes JVP/VJP through the existing native sparse-coefficient and transport kernels for transmitter position, scene vertices, and triangle material `eps_r` / `sigma_e`. Reflection-prefix diffraction tape replay rebuilds the prefix image source and power from recorded initial rays and primitive history so `R^n -> D` families propagate gradients through the prefix reflections. This is a pathwise estimator and intentionally does not add score-function terms for discrete edge, primitive, path, or visibility selection changes.
- `witwin.channel.montecarlo.Config(enable_bdpt_reflection_coupled_diffraction=False)` now disables BDPT reflection-coupled diffraction families while leaving ordinary reflection tracing available.
