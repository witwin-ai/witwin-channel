# Extended runtime exact-baseline profile (Plan 08 section 9 / gate G0 backfill)

This directory freezes the `extended` runtime profile for commit
`d2ba6979e41bc74766a21aa92293e3fb78444c46`. It is append-only: later work must
compare against these artifacts rather than overwrite them. It complements the
Phase-0 baseline at `0892d855b27ee851521a181f5158b0bf41091eda/` (static +
`reduced` runtime profile); it does not replace it.

## Purpose

The `reduced` profile covers only 8 cells (4 solvers x {empty-los,
single-reflection} x ad_mode=none). This `extended` profile backfills the
section-9 matrix dimensions that an accepted numerical-kernel change
(`docs/dev/standards/adr-010-native-scattering-kernels.md`: native CUDA
ownership of the torch-Kirchhoff scattering stage and the rough-reflection
`C_r` factor) can touch, frozen at the pre-change commit. Per the ADR
acceptance protocol, cells that do not exercise those ops must stay bitwise
identical after the migration; the scattering/rough cells carry the frozen
pre-change hashes for the tolerance comparison.

## Measurement

Generated by `tools/refactor_runtime_baseline.py --profile extended`
(collection may be chunked over `collect_extended` cell subsets; the artifacts
are identical either way). Every cell ran in 2 independent processes with 1
warmup and 7 steady repeats per process. A cell is frozen only if the semantic
result fingerprint, path identity, stable (timing-stripped) metadata
fingerprint, and scene-input fingerprint are byte-identical across processes;
launch/tape ledgers are also identical across processes for all 38 frozen
cells. Timings are trend data only. Another GPU workload ran concurrently on
this host during capture: hashes and launch counts are unaffected; treat the
timing distributions as noisy.

- Result: 38 cells frozen, 1 excluded (recorded in `excluded`, see below).
- Native binary: `artifacts/cmake-ad/_channel_native.cp311-win_amd64.pyd`,
  build fingerprint
  `e98544edb2f3ba5524044bee6d2421624172b6509199f51e849dd78c09bdea71`,
  RayD at the identity-lock commit
  `6047089cc7a41661402a02d40c96b9117e03a135`.
- Python 3.11.14, Torch 2.10.0 CUDA 12.8, NVIDIA SM 120 (per-process
  environment records are embedded in `runtime/extended-performance.json`).

## Frozen matrix

### Forward cells (`ad_mode=none`)

Scene builders are the canonical fixtures from `tests/support/scenes.py` and
`tests/deterministic/test_reflection_multibounce.py`; MC solvers use fixed
seeds (`coverage.mc_seeds`).

| Scenario | Component(s) | Solvers |
|---|---|---|
| `thin-wall-transmission` | transmission | path, deterministic, MC-basic, BDPT |
| `single-wedge-diffraction` | diffraction | path, deterministic, MC-basic, BDPT |
| `coupled-reflection-diffraction` | reflection+diffraction, `coupled_paths=True` | path, BDPT |
| `multibounce-reflection` | reflection, `max_depth=2`, two walls | path, deterministic, MC-basic, BDPT |
| `rough-scattering-ensemble` | scattering (ensemble Kirchhoff) | path, MC-basic, BDPT (deterministic excluded, see below) |
| `rough-scattering-realization` | scattering (realization_coherent phase screen) | deterministic |
| `rough-reflection-cr` | reflection only (coherent `C_r` attenuation, no scattering) | path, deterministic, MC-basic, BDPT |

The BDPT `single-wedge-diffraction` cell uses the public
`accumulation_strategy="staged"` (cell_reduce) option: the default atomic grid
accumulation is not bitwise stable across processes, while the staged
fixed-order reduction freezes exactly.

### AD cells (`ad_mode` in {jvp, vjp}; path and deterministic)

Gradient tensors are hashed with the same scheme as forward outputs, and the
AD launch/tape ledger (`ad_status`, `forward/backward/jvp_launch_count`,
`tape_bytes`) is frozen alongside.

| Scenario | jvp seed | vjp seed |
|---|---|---|
| `single-reflection` | material `eps_r` | material `eps_r` |
| `thin-wall-transmission` | material `layer_eps_r` | material `layer_eps_r` |
| `single-wedge-diffraction` | material `eps_r` | material `eps_r` |
| `rough-reflection-cr` | `frequency` (forward dual) | `frequency` |

Both rough-reflection AD cells seed frequency so the derivative flows through
`C_r` (`dC_r/df`) in forward and reverse mode - the exact contract ADR-010
op 3's jvp/backward companions must reproduce. A `layer_eps_r` dual produces
no forward tangent on rough-reflection rows, so frequency is the canonical
jvp seed there.

## Excluded cell

`rough-scattering-ensemble` / `deterministic` / `none`: the semantic result
hash differs across independent processes. Diagnosis: the per-path scattering
rows (exported `paths.*` tensors) are byte-identical across processes; only
the aggregated `component_fields["scattering"]`, `component_power
["scattering"]`, and `path_gain` differ, i.e. the float accumulation order of
the structural Torch row-sum. That aggregation is exactly the code ADR-010
does NOT migrate ("row compaction and RowCollector assembly stay Torch"), and
the per-row physics it does migrate is frozen bitwise via the path-solver
ensemble cell and the deterministic realization cell. The exclusion is
recorded machine-readably in the `excluded` array of `runtime/extended.json`.

## Section-9 dimensions covered elsewhere (not in this profile)

Listed in `coverage.unsupported_dimensions`:

- Munich reduced/full smoke: deterministic and BDPT Munich parity tests.
- Wheel/release and device/build matrices: fresh-clone and wheel CI tiers.
- MC statistics (PDF/MIS/event counts, variance-vs-N): MC seed-stability and
  statistics tests plus the statistical-gate benchmarks.
- Coupled R-D on deterministic / MC-basic: capability refusal
  (`supports_reflection_diffraction_coupling=False`).
- realization_coherent scattering on path / MC solvers: the canonical fixture
  is deterministic-only.
- AD on BDPT (ad_modes=["none"]), MC-basic AD (covered by
  `tests/ad/test_mc_basic_ad.py`), and scattering AD (fail-loud refusal on
  every differentiable solver).

## Artifact layout

- `runtime/extended.json`: immutable index (schema, measurement policy,
  coverage, exclusions, artifact SHA-256 checksums)
- `runtime/extended-solver-results.json`: exact per-cell result manifests for
  both processes (every tensor hash, alias groups, path identity, semantic and
  full fingerprints)
- `runtime/extended-launch-ledger.json`: aggregate launch/tape accounting per
  process (per-launch grid/block/stream detail remains unavailable, marked
  explicitly, never invented as zeros)
- `runtime/extended-performance.json`: 2x7 wall/CUDA timing and memory
  distributions plus per-process environment records (trend data)

## Re-freezing

The index is immutable per commit. To refreeze at a new pre-change commit:
RayD checked out at the identity-lock commit, quiescent tree, then
`python tools/refactor_runtime_baseline.py --profile extended` (witwin2
environment). Non-reproducible or capability-rejected cells are recorded in
`excluded`, never forced.
